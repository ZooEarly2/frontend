# 쥬얼리 프론트엔드

이주배경학생의 학교 적응을 돕는 한국어 말하기 연습 앱의 화면.

Vite + React + TypeScript. 브라우저에서 그대로 돌고, 빌드 결과(`dist/`)는 정적 파일이라
Azure Static Website / Static Web Apps 에 그대로 올린다.

## 무엇이 들어 있나

| 화면 | 하는 일 | 부르는 API |
|---|---|---|
| 온보딩 | 닉네임·모국어를 받아 기기에 저장 | — |
| 홈 | 오늘의 네 가지 · 진행도 · 동화 버튼 | — |
| 등교·급식·하교 | 표현 고르기 → 따라 말하기 → 발음 퀴즈 | `/pronunciation/sentences` `/pronunciation` `/tts` |
| 수업시간 | 국어책 쪽 찾기 → 동시 낭독 | `/pronunciation/sentences` `/pronunciation` `/tts` |
| 동화 | 하루치 4장면을 동화로 | `/story` |
| 메뉴 | 내 정보 수정 · 배운 문장 복습 | `/pronunciation/sentences` |

**서버는 사용자를 저장하지 않는다.** 닉네임·모국어·진행도·오늘의 기록은 전부 기기
(`localStorage`)에 있고, 요청할 때마다 실어 보낸다.

## 로컬에서 돌리기

```bash
npm install
cp .env.example .env.local     # 이미 있으면 건너뛴다
npm run dev                    # http://localhost:5173
```

게이트웨이(8080)와 추론 서버(8000)가 함께 떠 있어야 한다 — 저장소 루트의 README 참고.

### 마이크

브라우저는 **보안 컨텍스트**(https 또는 localhost)에서만 마이크를 연다.
`localhost:5173` 은 괜찮지만, 휴대폰에서 `http://192.168.x.x:5173` 으로 들어오면 녹음이
막힌다. 그때는 터널(`cloudflared`, `ngrok` 등)로 https 주소를 만들어 접속한다.

마이크를 못 쓰는 환경에서도 화면이 막히지 않는다 — 각 녹음 화면에 "마이크 없이
넘어가기" 우회 버튼이 뜬다.

### 동화 앨범

하루를 마치면 동화가 한 편 만들어지고, 그것이 **서버에 남는다.** 다음 날에도
메뉴 → *내 동화 앨범 보기* 에서 다시 읽는다.

앨범은 게이트웨이의 `/api/v1/albums` 에 있다(`/ai/*` 가 아니다 — 추론 중계가
아니라 게이트웨이가 직접 가진 데이터다).

**묶는 키는 닉네임이 아니라 기기가 만든 UUID 다**(`store/childId.ts`). 닉네임은
겹치고(같은 반에 "지우"가 둘) 바뀌므로(메뉴에서 이름 수정) 키로 쓰면 앨범이
섞이거나 통째로 사라진다. 닉네임은 "그때 그 이름"을 표지에 띄우기 위한 표시용으로
함께 보낸다.

`childId` 는 프로필(`zooearly.v1`)과 **다른 키에 저장한다.** 프로필은 날짜가
바뀌면 진행도가 비워지는데 그때 앨범까지 잃으면 안 되기 때문이다. 다만
"처음부터 플레이하기"는 기기를 다음 아이에게 넘기는 동선이라 그때는 신원도
새로 만든다 — 안 그러면 다음 아이가 앞 아이의 동화를 보게 된다.

저장은 **동화를 화면에 띄운 뒤**에 부른다. 저장을 기다렸다 보여주면 저장이 늦거나
실패하는 날 아이가 동화를 아예 못 본다.

읽는 화면은 오늘 만든 동화와 앨범에서 꺼낸 동화가 **같아야 하므로** `StoryBook`
한 곳에서만 그린다.

### 소리

문장 읽어주기는 **서버 TTS** 가 기본이다. 기기 내장 TTS 를 쓰지 않는 이유는 이 앱이
모국어(베트남어·중국어)도 읽어줘야 하는데, 그 언어팩이 없는 기기에서는 아무 소리도
안 나기 때문이다.

로컬 개발은 추론 서버가 목(mock)이라 실제 음성 대신 차임이 온다. 그때는 브라우저
음성합성으로 대신 읽어준다. `VITE_TTS_MODE` 로 고른다.

| 값 | 동작 |
|---|---|
| `auto` (기본) | 목 음성이면 브라우저로 읽고, 실제 음성이면 서버 음성을 재생 |
| `server` | 항상 서버 음성만 |
| `browser` | 서버를 부르지 않고 브라우저 음성만 (백엔드 없이 화면만 볼 때) |

#### 말풍선은 저절로 읽힌다

동물 캐릭터가 말풍선으로 하는 안내와 질문은 **뜨는 즉시 소리로도 나간다.**
이 앱을 쓰는 아이는 한국어를 아직 못 읽는다는 전제로 만들기 때문이다 — 글자만
띄우면 안내가 전달되지 않는다. `SpeechBubble` 이 스스로 읽으므로 화면마다 따로
부르지 않는다(`narrate={false}` 로 끌 수 있다).

말풍선 오른쪽 위의 작은 막대는 **지금 이 말풍선이 말하는 중**이라는 표시다.
누르는 버튼이 아니다 — 소리와 글자를 이어주는 단서다.

목소리는 `voice` 로 고른다. `TEACHER`(어른)와 `FRIEND`(또래)뿐이고 실제 성우는
서버가 정한다. 호랑이 친구만 `FRIEND` 다 — 또래를 어른 목소리로 읽으면 친구가
말을 건 것으로 들리지 않는다.

조용해야 하는 네 자리가 있다:

| 언제 | 왜 |
|---|---|
| 스플래시가 아직 덮고 있을 때 | 첫 화면은 스플래시 **아래에** 미리 그려진다. 거기서 읽어버리면 아이는 로딩 화면에서 목소리를 듣고, 화면이 열릴 땐 말이 끝나 있다 |
| 마이크가 열려 있을 때 | 스피커 소리가 그대로 녹음에 섞여 채점이 엉뚱해진다 |
| 메뉴에서 읽어주기를 껐을 때 | 교실처럼 여럿이 한 화면을 볼 때. 🔊 를 직접 누른 것은 여전히 들린다 |
| 앞말이 아직 나가는 중일 때 | 새 말이 시작되면 앞말은 멈춘다. **받아오는 중**인 요청까지 무효로 만든다 — 그러지 않으면 뒤늦게 재생돼 두 목소리가 겹친다 |

브라우저는 아이가 화면을 한 번 건드리기 전에는 소리를 막는다. 그래서 스플래시는
눌러서 건너뛸 수 있고(빗장이 그때 풀린다), 그래도 막힌 첫 마디는 **첫 터치 때**
읽어준다 — 다만 그 터치로 다음 말풍선이 떴다면 흘려보낸다. 지난 말을 뒤늦게 읽으면
화면과 소리가 어긋나 더 헷갈리기 때문이다.

## 빌드 · 배포

```bash
npm run build        # dist/
npm run preview      # 빌드 결과 확인
```

배포 시 `VITE_API_BASE_URL` 을 게이트웨이 주소로 바꾼다. 이 값은 **빌드 시점에
번들에 박히므로** 바꾼 뒤 반드시 다시 빌드해야 한다.

```bash
VITE_API_BASE_URL=https://<gateway>.azurecontainerapps.io npm run build
```

게이트웨이의 `CORS_ALLOWED_ORIGINS` 에 이 앱의 주소를 넣어야 브라우저가 요청을 통과시킨다.

라우팅은 해시(`/#/home`)를 쓴다. Azure Static Website 는 정적 파일만 서빙해서 경로
라우팅으로는 새로고침이 404 가 되는데, 해시는 그 문제를 아예 만들지 않는다.

## 구조

```
src/
├─ api/         게이트웨이 호출 (client: 봉투 해제·에러 정규화 / endpoints: 엔드포인트별)
├─ audio/       녹음(useRecorder) · 읽어주기(speaker, 캐시 포함)
├─ components/  말풍선·버튼·마이크·캐릭터 등 공통 부품
├─ scenarios/   시나리오 콘텐츠(문구·배경·상대 캐릭터)
├─ screens/     화면
├─ store/       기기에 저장하는 상태 (프로필·진행도·오늘의 기록)
└─ styles/      디자인 토큰 · 전역 스타일
```

### 첫 로딩 화면

`public/loading.jpg` 를 스플래시로 띄운다(`screens/Splash.tsx`). 기다리게만 하는 화면이
아니라, 머무는 동안 **첫 화면이 쓸 그림과 글꼴을 미리 받는다** — 그러지 않으면 온보딩에
들어간 뒤 캐릭터가 한 박자 늦게 튀어나오고 글자가 한 번 갈아끼워지며 튄다.

원본(827×1902)의 좌우에 가장자리 색을 늘려 붙여 화면비를 0.62 로 넓혀 뒀다. 덕분에
`cover` 로 꽉 채워도 **잘려 나가는 것은 늘린 여백뿐이고 그림은 온전히 남는다.**
로고나 리본이 기기 폭에 따라 먹히지 않는다.

### 아이콘 — 이모지를 쓰지 않는다

세 가지 이유가 있다.

1. 기기마다 그림이 다르다. 같은 🎤 가 안드로이드·iOS·윈도우에서 각각 다른 색과 굵기로
   떠서 앱 팔레트와 어긋난다.
2. **윈도우는 국기 이모지를 그리지 않는다.** 🇰🇷 가 "KR" 이라는 글자 두 개로 떨어진다 —
   한글을 아직 못 읽는 아이가 자기 언어를 찾아야 하는 자리라 기능이 통째로 사라진다.
3. 이모지는 글자라 크기·정렬이 글꼴에 끌려다닌다. 버튼 안에서 미세하게 어긋난다.

그래서 `components/Icon.tsx` 에 24 그리드 · 2px 선 · 둥근 끝으로 직접 그렸다.
국기도 SVG 다. 보석은 `components/Gem.tsx` 로 따로 뒀다.

### 글꼴

두 벌만 쓰고, 둘 다 `public/fonts` 에 직접 담는다 — 외부 CDN 이 막히거나 느린
환경에서도 글자가 한 번 갈아끼워지며 튀지 않는다.

| 자리 | 글꼴 | 왜 |
|---|---|---|
| 버튼 · 제목 · 말풍선 · 본문 | Pretendard | 획이 곧고 균일해 작은 글씨도 또렷하다 |
| 카드 안 설명 · 동화 내레이션 | omyu pretty | 손으로 적어 준 듯한 결. "선생님이 건네는 말" 자리 |

한글은 **KS X 1001 상용 2350자만** 담았다. 음절 전체(11172자)를 담으면 손글씨체인
omyu pretty 하나가 3.4MB 라 첫 화면이 그만큼 늦어진다. 2350자로도 아이 이름을 포함해
실제로 쓰이는 글자는 사실상 모두 들어간다. 없는 글자는 시스템 글꼴로 떨어진다.

새 글꼴을 넣거나 범위를 바꾸려면 원본(`ZooEarly-FE-dev/.../assets/fonts`)에서
`fontTools` 로 다시 서브셋한다.

### 이름에 조사를 붙이지 않는다

`{이름}야, 안녕!` 이 아니라 `안녕, {이름}!` 으로 쓴다. 이 앱을 쓰는 아이의 이름은
한국 이름만이 아니다 — 경빈이면 "경빈아", Linh 이면 조사 자체가 어색하다. 어떤 규칙을
넣어도 틀리는 이름이 남으므로, 문구에서 조사를 아예 없앴다.
(`lib/korean.ts` 에 호격 헬퍼가 있지만 피할 수 없는 자리에서만 쓴다.)

### 말해보기 갈래는 없다

예전에는 인트로에서 "말해보기"(마이크로 자유롭게 답하고 `/stt` + 표현 교정을 받는 길)와
"선택해보기"가 갈렸다. 말해보기는 뺐다 — 무엇을 말해야 할지 모르는 상태에서 마이크부터
들이대면 대부분 아무 말도 못 하고, 그 갈래를 지나야 나오는 화면이 둘 더 있어 흐름도 길었다.
지금은 표현을 먼저 보여주는 한 갈래뿐이다.

게이트웨이의 `/stt`·`/feedback` 은 그대로 살아 있다. `api/endpoints.ts` 의 함수도 남겼다 —
나중에 그 화면을 만들면 부르기만 하면 된다.

### 보석 네 개를 다 모았을 때

하교까지 마치고 홈으로 돌아온 그 한 번, 화면을 덮고 축하한다(`screens/StoryUnlock.tsx`).
보석 넷이 가운데로 모여 빛으로 터지고, 그 자리에 동화책이 나타나고, 안내 부엉이가 말을 건다.
**하루에 한 번만** 나온다 — 홈에 돌아올 때마다 터지면 축하가 아니라 방해다.
그 뒤로는 동화 버튼에 빛이 한 번씩 스쳐 지나가 계속 눈에 띈다.

### 보석

앱 이름이 "쥬얼리"다. 시나리오를 마치면 별이 아니라 **카테고리마다 색이 다른 보석**을
하나씩 받는다(등교 분홍 · 수업 민트 · 급식 노랑 · 하교 보라). 홈 배너에 빈 자리까지
함께 보여줘서, 글자를 못 읽는 아이도 몇 개가 더 필요한지 센다. 네 개를 모으면 동화가 열린다.

### 캐릭터

`public/characters/` 의 스프라이트는 원본 시트(`character_me.png`,
`character_teacher.png`)를 다섯 포즈로 잘라낸 것이다.

| 포즈 | 언제 |
|---|---|
| `hello` | 인사·대기 |
| `speak` | 말하는 중·녹음 중 |
| `happy` | 알아들었을 때 |
| `sad` | 아쉬울 때 |
| `cheer` | 잘했을 때 |

`me` 는 주황 고양이(이주배경학생), `teacher` 는 흰 토끼(안내·선생님)다.
배경 일러스트에도 같은 두 캐릭터가 그려져 있어 세계관이 이어진다.

**배경이 또렷한 화면(인트로·완료)에는 스프라이트를 얹지 않는다.** 그 그림들에는 이미
주인공이 그려져 있어서, 위에 또 얹으면 같은 아이가 두 번 나온다. 스프라이트가 서는
화면은 배경 초점을 흐린다.

예외가 등교하기다. 원래 배경(`bg_arrival_intro`)에는 분홍 원피스 토끼가 한가운데 서
있었는데, 그 위에 호랑이 친구의 말풍선을 띄우니 **토끼가 말하는 것처럼 읽혔다.** 배경에서
인물을 지운 빈 거리(`bg_arrival_street`)로 바꾸고, 말하는 캐릭터를 직접 세웠다.
어느 쪽인지는 시나리오의 `introActors` 가 정한다.

### 상대 캐릭터 그림은 전부 흉상이다

호랑이·코끼리·부엉이·기린·급식 선생님 — 다섯 장 모두 가슴에서 잘려 있다(맨 아랫줄이
불투명하다). 화면 아래에 붙여 쓰라고 만든 그림이라 공중에 띄우면 잘린 단면이 그대로
드러난다. `PartnerActor` 가 아래 16%를 지워 그리고(`actor--bust`), 배치할 때는 바로 아래
카드·목록에 살짝 파묻는다(`actors--grounded`). **화면 한가운데 홀로 놓지 말 것.**

말풍선은 말하는 캐릭터 **바로 위**에 붙인다(`talk-group`). 위아래로 떨어뜨리면 누가 한
말인지 이어지지 않는다.
